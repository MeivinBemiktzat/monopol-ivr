# מונופול טלפוני – IVR ימות המשיח + Vercel

מערכת מלאה למשחק מונופול (לוח ישראלי - ערים) דרך שלוחת `type=api` בימות המשיח,
עם שרת Node.js על Vercel ומסד נתונים Upstash Redis לשמירת מצב המשחקים.

## מבנה הפרויקט

```
monopoly-ivr/
├── api/
│   ├── ivr.js       ← כל לוגיקת המשחק (handler יחיד)
│   └── board.json   ← לוח המשחק (ערים, מחירים, שכירויות)
├── package.json
├── vercel.json
└── README.md
```

3 קבצי קוד/דאטה בלבד: `ivr.js`, `board.json`, `package.json` (+ vercel.json קונפיגורציה בלבד, לא לוגיקה).

## שלב 1: פריסה ל-GitHub + Vercel

1. חלצו את קובץ ה-ZIP לתיקייה במחשב שלכם.
2. צרו repository חדש וריק ב-GitHub (ללא README, כדי לא ליצור קונפליקט).
3. בתיקייה שחילצתם:
   ```bash
   git init
   git add .
   git commit -m "Monopoly IVR initial commit"
   git branch -M main
   git remote add origin https://github.com/<your-username>/<your-repo>.git
   git push -u origin main
   ```
4. היכנסו ל-[vercel.com](https://vercel.com) → **Add New Project** → בחרו את ה-repo שיצרתם.
5. Framework Preset: **Other** (זה לא Next.js, זו Serverless Function רגילה – Vercel מזהה את `api/ivr.js` אוטומטית).
6. **לפני הפריסה**, הוסיפו את משתני הסביבה הבאים תחת Project Settings → Environment Variables:

   | שם המשתנה | ערך | חובה? |
   |---|---|---|
   | `UPSTASH_REDIS_REST_URL` | כתובת ה-REST של מסד הנתונים הייעודי שלכם ב-Upstash | כן |
   | `UPSTASH_REDIS_REST_TOKEN` | הטוקן של אותו מסד נתונים | כן |
   | `YEMOT_USERNAME` | שם משתמש למערכת ימות (למשל `0771234567` או `0771234567/0000`) | לא (רק אם רוצים הודעות מותאמות אישית) |
   | `YEMOT_PASSWORD` | סיסמת ה-API של ימות | לא (כנ"ל) |
   | `YEMOT_EXT_PATH` | נתיב השלוחה שבה יישמרו קבצי ה-TTS המותאמים אישית, למשל `ivr2:monopoly` | לא (כנ"ל) |

   **חשוב:** ודאו שמסד ה-Upstash הזה **ייעודי לפרויקט הזה בלבד** ואינו משותף עם פרויקטים אחרים – המפתחות בקוד כבר מבודדים בקידומת `monopoly:`, אך עדיף עדיין מסד נפרד.

7. לחצו **Deploy**. בסיום תקבלו כתובת כמו:
   ```
   https://monopoly-ivr-yourname.vercel.app/api/ivr
   ```
   זו הכתובת שתגדירו כ-`api_link` בשלוחת ימות (שלב הבא).

## שלב 2: הגדרת השלוחה בימות המשיח

צרו שלוחה חדשה מסוג `type=api` (למשל תחת התיקייה הראשית, שלוחה `5`).
בקובץ `ext.ini` של השלוחה, הגדירו:

```ini
type=api
api_link=https://monopoly-ivr-yourname.vercel.app/api/ivr
api_url_post=yes
api_wait_answer_music_on_hold=yes
api_log=yes
```

זהו! זו כל ההגדרה הנדרשת בצד ימות – כל שאר הלוגיקה (השאלות, הקוביות, הקנייה,
הבנייה וכו') מגיעה בתשובות מהשרת שלכם בזמן אמת (`id_list_message`, `read`,
`go_to_folder`), כמו שמוגדר במודול ה-API של ימות.

### הערה על "פתיחת קו" ומספר טלפון
כל שחקן צריך להתקשר למספר של המערכת ולהיכנס לשלוחה הזו. ניתן להריץ עד 6 קווים
מקבילים (תלוי בחבילת ימות שלכם) כדי שכמה שחקנים יוכלו להתקשר ולשחק במקביל
לאותו משחק.

## שלב 3: מנגנון ההודעות המותאמות אישית (s1010 וכו')

כפי שביקשתם – לכל הודעה במערכת יש **קוד ייחודי** (למשל `s1010`).

**איך זה עובד בפועל:**
- ימות תומך באופן טבעי בתכונה הזו דרך סוג ה-`Speech` (`s-`) בפקודת
  `id_list_message`: אם קיים בשלוחה קובץ `s1010.tts` (טקסט להקראה) המערכת
  תקריא אותו; אם לא קיים – יש להשתמש בסוג `Text` (`t-`) עם הטקסט הרגיל.
- השרת שלנו (`ivr.js`) **בודק אוטומטית**, דרך ה-API הניהולי של ימות
  (`GetTree`), אילו קבצי `sXXXX` קיימים כרגע בשלוחה שהגדרתם ב-`YEMOT_EXT_PATH`,
  ובוחר אוטומטית `s-` (קובץ מותאם) או `t-` (טקסט ברירת מחדל) בהתאם.
- **כדי להתאים הודעה אישית:** פשוט העלו לשלוחת ימות (בתיקיית ה-`YEMOT_EXT_PATH`
  שהגדרתם) קובץ TTS בשם התואם לקוד ההודעה (למשל `s1010.tts`, המכיל את הטקסט
  להקראה, ראו את מדריך ה"הקראת טקסט" של ימות ליצירת קבצי `.tts`).
- אם הקובץ לא קיים – המערכת פשוט תשתמש בטקסט ברירת המחדל שמוגדר בקוד, ללא
  צורך בשום פעולה נוספת.

**רשימת קודי ההודעות בפרויקט** (לשימושכם, אם תרצו להתאים הודעות ספציפיות):

## שלב 4: זרימת המשחק (איך זה עובד)

1. **מסך פתיחה:** "1" ליצירת משחק חדש, "2" להצטרפות למשחק קיים.
2. **יצירת משחק:** שואל כמות שחקנים (2-6) → נותן קוד בן 3 ספרות → מבקש שם
   (הקלדה במקלדת הטלפון).
3. **הצטרפות למשחק:** מבקש קוד בן 3 ספרות → מבקש שם.
4. כאשר כל השחקנים המוגדרים הצטרפו – המשחק מתחיל אוטומטית.
5. **בתורו של שחקן** (מזוהה לפי `ApiCallId` הייחודי לשיחה שלו):
   - שומע את מצבו האישי (כסף) ותפריט: 1=קוביות, 2=מצב אישי, 3=בנייה, 4=סיום תור.
   - הטלת קוביות מזיזה אותו בלוח, וגם שולחת שידור לכל שאר השחקנים (`broadcastLog`)
     שהם שומעים כשמגיע תורם להאזין (לדוגמה: "דני קנה את טבריה, עלות 120 שקלים").
   - נחיתה על נכס פנוי → הצעת קנייה. נחיתה על נכס תפוס → תשלום שכירות אוטומטי.
   - "לך לכלא", מסים, קופה קהילתית, חניה חינם (ללא כסף – לפי הכללים הרשמיים)
     – מטופלים אוטומטית.
   - דאבל בקוביות → תור נוסף. 3 דאבלים ברצף → כלא.
   - בנייה: בונה אוטומטית על הנכס הזמין הראשון בקבוצת צבע מלאה (שמורה בהתאם
     לכללי הבנייה המאוזנת בגרסה הפשוטה של המשחק הטלפוני).
   - פשיטת רגל: המערכת מנסה למשכן נכסים אוטומטית; אם עדיין אין מספיק כסף,
     השחקן פורש, נכסיו חוזרים לבנק, וממשיכים עד שנשאר שחקן אחד – שמוכרז כמנצח.
6. **שחקנים אחרים** ששומעים באותו רגע (לא בתורם) שומעים עדכון אחרון ומחכים
   לתורם בלולאה קלה (polling), כך שכל שחקן שומע את מה שקורה למרות שכל אחד
   בשיחה נפרדת משלו.

## שלב 5: בדיקות מומלצות לפני production

- שיחת בדיקה ליצירת משחק דו-שחקני, ולוודא שהצטרפות שחקן שני עובדת עם הקוד.
- ניתוק שיחה באמצע (hangup) – ולוודא שהשחקן יכול לחייג חזרה ולהמשיך (המצב
  נשמר ב-Redis כל עוד לא עברו 12 שעות).
- בדיקת תרחיש פשיטת רגל (למשל התחילו עם מעט כסף היפותטית ע"י שינוי `startMoney`
  זמנית בקובץ board.json בסביבת בדיקה).
- בדיקת "לא נגמר הקובץ" – אם `YEMOT_EXT_PATH` לא הוגדר, המערכת פשוט תמיד
  תשתמש בטקסט הרגיל (t-), לא תיפול.

## Rollback

אם צריך לחזור אחורה: ב-Vercel Dashboard → Deployments → בחרו פריסה קודמת →
**Promote to Production**. מצב המשחקים ב-Redis לא נמחק בין פריסות קוד.
